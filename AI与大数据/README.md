# AI与大数据 — 事实与约束资料夹

本目录不是「随手写的笔记」，而是项目的**知识边界**所在：它规定 AI 可以说什么、不可以说什么，
以及说到哪一步必须停下来拒答。所有文件都参与 BM25 检索，因此文件里的每句话都可能被引用，
写入前请确认它是**可核验的事实**，而不是猜测。

## 目录内容

| 文件 | 作用 |
| --- | --- |
| `PROJECT_FACTS.md` | 唯一事实基线：范围白名单、事实基线表、禁止事项、拒答模板 |
| `README.md` | 本说明：目录定位、双层约束如何落地、维护规则 |

## 双层反幻觉约束怎么落地

```text
第一层（行为）：仓库根 agent.md
  ├─ 先检索后回答：任何事实必须来自 query/answer 的检索证据
  ├─ 单一事实源：项目事实只认本目录 PROJECT_FACTS.md
  ├─ 无命中即拒答：低分/无关/越界 → 原样输出拒答模板
  └─ 禁止编造清单：路径、行号、哈希、参数、数字、引用

第二层（内容）：本目录 PROJECT_FACTS.md
  ├─ 范围白名单 §2：W1–W5 五个可回答主题，各自绑定证据文件
  ├─ 事实基线 §1：仓库、语料源、命令、许可证等稳定事实
  ├─ 禁止事项 §3：六条硬性禁止
  └─ 拒答模板 §4：脚本直接读取，保证文本与基线同源
```

两层同时生效：`agent.md` 保证「一定会去检索」，`PROJECT_FACTS.md` 保证「检索结果怎么用」。
只有前者会出现「检索了越界内容却照答」；只有后者会出现「知道边界但懒得检索」。

## 维护规则

1. 新增主题 → 先在 `PROJECT_FACTS.md` §2 增加白名单条目，并绑定证据文件；
2. 新增语料 → 修改 `rag/rag_github.py` 的 `SOURCES` 后执行 `python rag/rag_github.py ingest`；
3. 改完必须重跑 `bash scripts/run_all.sh`，让 `output/` 留档与文字描述同步；
4. 任何未写进本目录的事实，都不算项目事实，不得进入回答。
